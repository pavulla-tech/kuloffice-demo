= KulOffice local stack
:toc: left
:toclevels: 2
:icons: font
:source-highlighter: highlight.js

Everything needed to test kuloffice end to end on one machine, in one compose
file, configured by one command.

== What runs

[cols="1,3"]
|===
|Service |What it is

|`keycloak`, `realm-setup`
|Keycloak with intaka's phone authenticator, and the `demo` realm with its clients and phone flows (web, passkey, mobile, token panel, and the `demo-backend` admin client)

|`kuloffice`, `bootstrap`
|kuloffice, built from your checkout. `bootstrap` activates a license and registers Keycloak as the identity provider.

|`web`
|The KulPay web app

|`token-panel`
|intaka's token panel: signs phone numbers in and keeps their tokens fresh

|`sms-inbox`
|intaka's demo backend. Where every SMS goes - Keycloak's codes and kuloffice's messages, so nothing reaches a real phone - and the demo page and API for intaka's demo app (`demo/run-android.sh`, `demo/run-ios.sh` there). This is the local stack intaka's demo used to bring up itself.

|`minio`, `minio-init`, `fileserver`
|MinIO with the `test` and `kyc-pending` buckets (pending images expire after a day), behind the boquisso file server

|`db`
|PostgreSQL 17, with kuloffice's and Keycloak's databases
|===

MiniAiLive and BLNK are not part of the stack: kuloffice uses their hosted
instances. Approving a KYC therefore creates a real identity on the hosted
BLNK. Set `BIOMETRICS_ENABLED=false` in `stack.env` to skip MiniAiLive and
send every submission to a reviewer.

== Prerequisites

* Docker with Compose v2, and Make
* `openssl` (for the license key pair)
* Sibling checkouts of the repositories the images are built from:
+
[source]
----
kuloffice/                      github.com/pavulla-tech/kuloffice
keycloak-phone-authenticator/   github.com/pavulla-tech/intaka
kulpay-web/                     github.com/pavulla-tech/kulpay-webapp
boquisso-fileserver/            github.com/pavulla-tech/boquisso-fileserver
kuloffice-demo/                 this repository
----
+
Other locations go in `stack.env` (`KULOFFICE_DIR`, `INTAKA_DIR`, `WEB_DIR`,
`FILESERVER_DIR`). Each image is built from whatever branch its checkout has
checked out.

== Quick start

[source,bash]
----
make up
----

The first run creates `stack.env`, generates the license key pair in
`.stack/keys`, builds every image, and configures the realm, buckets, license
and identity provider. It finishes by printing the URLs:

[cols="1,2,2"]
|===
|What |URL |Credentials

|Web app |http://localhost:3000 |a phone number; the code is in the SMS inbox
|Token panel |http://localhost:8765 |the same
|kuloffice API |http://localhost:18080 |`admin@kulpay.local` / `localadmin` (HTTP Basic, system routes)
|Keycloak |http://localhost:8080/auth/admin |`admin` / `admin`
|SMS inbox |http://localhost:8090/api/dev/inbox |
|intaka demo page |http://localhost:8090 |a phone number; the code is in the SMS inbox
|MinIO console |http://localhost:9001 |`kulstack` / `kulstack-local`
|File server |http://localhost:8082 |
|PostgreSQL |localhost:5432 |`kuloffice` / `kuloffice`
|===

Every step is skipped when already done, so `make up` is also how to apply a
change: it rebuilds what changed and restarts it.

== Make targets

[cols="1,3"]
|===
|`make up [PRESET=…] [KEYCLOAK=… KULOFFICE=… WEB=…]` |Build or pull, start and configure what runs here (see "Local, Docker Hub or server")
|`make plan [same options]` |What `make up` would run here and use on the server, without starting anything
|`make where` |What the last `make up` runs here, and the server addresses it uses
|`make down` |Stop the stack (data is kept)
|`make rebuild [S=service]` |Rebuild from the checkouts and restart
|`make restart [S=service]` |Restart
|`make logs [S=service]` |Follow logs
|`make ps` |What is running
|`make sms` |Print the SMS inbox
|`make reviewer` |Re-seed the demo reviewer (operator, identity, role)
|`make review ACCOUNT=acc_...` |Decide an account's KYC as the demo reviewer (`OUTCOME=approve\|reject\|request_documents`, `MESSAGE=`, `DOCS=`)
|`make kuloffice` |Recreate kuloffice with `stack.kuloffice.env` (MiniAiLive etc.)
|`make ussd-test` |Drive intaka's USSD channel end to end against this Keycloak
|`make psql` |psql into kuloffice's database
|`make bootstrap` / `make realm` / `make buckets` |Re-run one configuration step
|`make license` |Print a new license key signed with the stack's key
|`make clean` |Remove the containers and volumes (keys and `stack.env` stay)
|`make legacy-stop` |Stop the older `demo` + `kuloffice-demo` containers, which use the same ports
|===

== Local, Docker Hub or server

Keycloak, kuloffice and the web app can each run here from your checkout, run
here from a Docker Hub image, or not run here at all, the deployed one being
used instead. Set it in `stack.env`, or for one run on the command line:

[cols="1,3"]
|===
|`build` |Built here from its sibling checkout (`*_DIR`), as before
|`v0.1.0-alpha03` |That tag of `developerspavs/kulpay-*`, pulled and run here (amd64: emulated, slower, on Apple Silicon)
|`release` |The newest `v*` tag on Docker Hub, run here
|`server` |Not run here; the deployed one is used (`SERVER_*` settings)
|===

[source,sh]
----
make up PRESET=web          # the web app here; Keycloak and kuloffice on the server
make up PRESET=kuloffice    # web and kuloffice here; Keycloak on the server
make up PRESET=local        # everything here (the default stack.env)
make up WEB=build KULOFFICE=server KEYCLOAK=server   # any mix
make up KULOFFICE=release WEB=server                 # what's released, run here
make plan PRESET=kuloffice  # check a combination first
----

The supporting services follow: Postgres and the SMS inbox when Keycloak or
kuloffice run here, MinIO and the file server (`FILESERVER=build` or a tag)
with a local kuloffice, the realm and demo reviewer with a local Keycloak. The
token panel always runs; sign it in to whichever Keycloak `make where` lists.

*The server never calls this laptop.* That decides what can mix:

* *kuloffice on the server with Keycloak here:* refused. The server's
  kuloffice only accepts the server's tokens.
* *The web app here, kuloffice on the server:* you work on the server's real
  data. The server's Keycloak must accept `http://localhost:<WEB_PORT>`: its
  `DEV_WEB_ORIGINS` (default `http://localhost:3000`), applied by
  Actions → Server → `provision`.
* *kuloffice here, Keycloak on the server:* you sign in with your server
  account, but this kuloffice has its own database, so you onboard again here;
  the server's data is never touched. Needs `SERVER_ADMIN_CLIENT_SECRET` and
  `SERVER_WORKFORCE_API_SECRET` (the server's `ADMIN_CLIENT_SECRET` and
  `WORKFORCE_API_SECRET`). To make your staff account a reviewer here, also
  `SERVER_KC_ADMIN_PASSWORD` and `SERVER_REVIEWER_EMAIL`.
* *QR codes with a local kuloffice:* through the server's Solange, with
  `SOLANGE_API_KEY` (a test key from Solange's console). Its scan webhooks
  can't reach this laptop.
* *The deployed web app* never uses anything running here.

A kuloffice image from Docker Hub only takes the official license: set
`SERVER_LICENSE_KEY` (the server's `KULOFFICE_LICENSE_KEY`). A local build
signs its own (`make keys`). Switching one database between the two is fine:
bootstrap replaces a license that doesn't verify.

To try a combination beside your usual stack, give it its own name and ports,
e.g. `make up PRESET=web STACK_NAME=kultest WEB_PORT=3000 KC_PORT=38080 …`.

== How it fits together

A token's issuer is `http://localhost:8080/auth/realms/demo`. kuloffice and
the web app fetch that URL from inside their containers. So Keycloak,
kuloffice, the web app and the token panel all share the network namespace of
a container named `net`, which publishes their ports. For them, `localhost`
is the same place as it is for your browser.

As a result, each of these services listens inside on the same port it is
published on. To move a port, change it in `stack.env`; nothing else needs to
change, not even the issuer. That also lets a second copy run beside another
stack: give it a different `STACK_NAME` and different ports.

Ports are published on `127.0.0.1` (`STACK_BIND`). The token panel holds live
tokens and is always on loopback only.

== Files

[source]
----
docker-compose.yml     the stack
docker-compose.kuloffice-only.yml  the older kuloffice + database compose, with .env
                       (docker compose -f docker-compose.kuloffice-only.yml --env-file .env up -d)
stack.env.example      settings, copied to stack.env on first run
stack/bootstrap.sh     license activation and IdP registration
stack/token-panel.py   runs intaka's token panel in a container
stack/seed_reviewer.py makes the workforce realm's demo user a kuloffice reviewer
stack/review.py        decides a KYC review as that reviewer (make review)
stack/postgres/        creates Keycloak's database
.stack/keys/           license key pair (generated, gitignored)
----

`docker-compose.override.yml`, if you have one, belongs to the older setup.
The Makefile names `docker-compose.yml` explicitly, so it is never merged in.
